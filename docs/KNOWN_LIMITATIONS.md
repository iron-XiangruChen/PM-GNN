# Important reproducibility limitations and factual qualifications

## 1. Stale checkpoint split TAG versus executed split (important correction)

The **filenames/config tags** of all four author-supplied checkpoint archives say
`rock_group_9train_2val`, but the **actual executed PM-GNN notebook output** explicitly
prints `rock_group_8train_3val` with **5,777 training** and **2,081 validation** graphs.
The source notebook sets `N_VAL_ROCKS = 3`, yet defines `SPLIT_MODE =
"rock_group_9train_2val"` once early on and never updates this label even though
it computes a correct runtime `split_method` after selecting 8/3.

Therefore **the filename/config tag is demonstrably stale and must NOT be treated
as proof that the model actually trained with 9/2**. The archived weights are copied
**without renaming their `.weights.h5` files** for external inference compatibility,
but are stored under `*_saved_tag_9train_2val` to distinguish the stale label from
the actual experimental split. We cannot independently guarantee these checkpoints
were generated by exactly the printed 8/3 notebook run, though the available logs
strongly support that interpretation. The four packaged training notebooks now contain
one **metadata-only fix** immediately after split selection: `SPLIT_MODE = split_method`.
This does not change which rocks are trained/validated or model calculations; it only
makes future saved filenames/configs correctly report 8/3.

External inference notebooks default to the provided saved-tagged PM-GNN checkpoint
directory. Verify checkpoint/scaler correspondence before further experiments.

## 2. Training time versus total wall-clock cost

Recorded full PM-GNN training = 2,562.39 s (1,647.55 for permeability + 914.84
for modulus), baseline = 655.97 s. Ratio ~3.91x, an increase of ~291%.
This covers training and does NOT separately measure PNM extraction, path descriptor
precomputation, inference, or end-to-end runtime. Early stopping epochs differ.

## 3. Algorithm versus originally depicted flowchart

`compute_flow_path_descriptors` computes multi-source shortest paths, minimum-resistance
path proxies, widest bottleneck paths, conductance summaries, and tortuosity statistics.
The PMGNN model concatenates fixed global/path descriptor inputs and uses basic
neighbor-mean message passing followed by graph mean pooling. There is no explicit
k-shortest path enumeration, max-flow solver, per-path neural encoder, per-path
projection to traversed nodes, or LayerNorm/residual path fusion as depicted in **original Figure 4(c,d)**.
Original Figure 5 is substantially aligned with the implemented architecture and
does not need to be redrawn; Figure 4(a) additionally labels a 128-dimensional
encoder whereas the implemented hidden dimension is 64.

## 4. Grayscale thresholds and historical script comments

11-sandstone generator sets `PORE_MIN = 0`, `PORE_MAX = 60` (histogram selection rationale
was not captured in supplied script). External example notebooks currently set:
`mineral = 0` (binary/equal), `mtsimon = 60`, `yulaiLR-SR = 80`, `EF-78 = 70`, and
optional `EF-75 = 55`. External thresholds were reported by the author to be selected
from each CT grayscale distribution, not tuned against reference properties.
Some historical comment lines mention different thresholds: for reproducibility,
**actual executable assignments** should be treated as operative; verify original
experiment logs before attributing a numerical setting to published results.

## 5. External Mt Simon voxel-size metadata mismatch

The code line in the supplied `mtsimon_gs_1200_8bit_PM_GNN_prediction.ipynb`
sets `VOXEL_SIZE_UM = 2.25`, whereas a nearby comment calculates **2.8 μm** from
3.36 mm / 1,200, and the manuscript data table uses **2.8 μm**. The packaging process
deliberately did not silently change the numerical setting. Confirm which resolution
was actually used to generate the reported external results before publication.

## 6. Reproducibility and testing

Only static JSON/syntax and package integrity checks were performed. Full physical
simulation/training tests were not possible without the author's CT/PNM datasets and
validated library/runtime versions. Package dependency ranges are proposed, not a
historical `pip freeze`/CUDA record. Model `.pkl` files are unsafe from untrusted
sources; these particular files are copied from the user-provided archive, and users
should only load them when they trust that archive.

## 7. Data and code release

The 28MB original master CSV is not included because it embeds the author's local
Windows filesystem paths and references missing per-sample PNM Excel files. For a
fully reproducible release, publish a sanitized dataset manifest with portable
relative paths and the corresponding PNM graph files (subject to rights/storage),
or provide a DOI to an external archive.
